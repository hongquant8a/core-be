================================================================================
BE CHANGELOG — 2026-05-18 — Multi-attachment cho thảo luận / chất vấn
================================================================================

Theo requirement.txt: "Đính kèm cho thảo luận, chất vấn là cho thêm nhiều,
dạng thêm danh sách: STT, Tên tập tin, Tập tin đính kèm".

Trước: 1 đăng ký = 1 file đính kèm (qua field media_id).
Sau:   1 đăng ký = nhiều file (qua table riêng + nested API).


────────────────────────────────────────────────────────────────────────────────
1. SCHEMA
────────────────────────────────────────────────────────────────────────────────

Table mới: meeting_discussion_registration_attachments
  - id
  - organization_id
  - meeting_discussion_registration_id (FK cascade)
  - media_id (FK media — file thực)
  - file_name (string nullable) — TÊN HIỂN THỊ do user đặt
  - sort_order (int)
  - timestamps

Migration tự động COPY data cũ: mỗi registration có media_id != null → tạo 1
row attachment với file_name = original media filename. FE không mất file cũ.

Field cũ `meeting_discussion_registrations.media_id` GIỮ NGUYÊN cho backward
compat — FE/code cũ vẫn đọc được. Sẽ drop ở migration riêng sau khi FE
chuyển hết sang field attachments.


────────────────────────────────────────────────────────────────────────────────
2. RESOURCE THAY ĐỔI
────────────────────────────────────────────────────────────────────────────────

MeetingDiscussionRegistrationResource response giờ có thêm field `attachments`:

  {
    "id": 221,
    "content": "Đề nghị làm rõ tình hình thu chi quý 1",
    ...

    // Legacy single (giữ cho FE cũ, sẽ deprecate):
    "media_id": 346,
    "file_url": "/storage/346/old.docx",
    "file_name": "old.docx",

    // MỚI: multi-file list, FE mới dùng cái này.
    "attachments": [
      {
        "id": 1,
        "meeting_discussion_registration_id": 221,
        "media_id": 346,
        "file_url": "/storage/346/old.docx",
        "file_name": "Slide trình chiếu",        // user-defined display name
        "original_file_name": "old.docx",        // raw filename khi upload
        "sort_order": 0,
        "created_at": "10:00:00 18/05/2026",
        "updated_at": "10:00:00 18/05/2026"
      },
      ...
    ]
  }

FE hiển thị list theo cột yêu cầu:
  STT | file_name (tên tập tin user đặt) | file_url (tập tin đính kèm — link tải)


────────────────────────────────────────────────────────────────────────────────
3. API ENDPOINT MỚI
────────────────────────────────────────────────────────────────────────────────

3.1 Thêm file đính kèm
  POST /api/meetings/{meeting}/discussion-registrations/{r}/attachments
  Gate: can:update,meetingDiscussionRegistration
        (owner đăng ký HOẶC chair/op meeting — đồng bộ policy update của registration)

  Body (multipart):
    file       file    required   Tệp đính kèm (≤10MB)
    file_name  string  optional   Tên hiển thị user đặt. Bỏ trống → dùng tên gốc file upload.
    sort_order int     optional   Thứ tự (default = max+1)

  meeting_discussion_registration_id auto-inject từ URL — FE không cần gửi.

  Response 201:
    { "success": true, "message": "Thêm tệp đính kèm thành công!", "data": { ...attachment } }


3.2 Sắp xếp lại thứ tự
  PATCH /api/meetings/{meeting}/discussion-registrations/{r}/attachments/reorder
  Gate: can:update,meetingDiscussionRegistration

  Body:
    items  object[]  required
           Mỗi item: { id, sort_order }

  Response 200: { "success": true, "message": "Sắp xếp tệp đính kèm thành công!" }


3.3 Xóa file
  DELETE /api/meetings/{meeting}/discussion-registrations/{r}/attachments/{a}
  Gate: can:delete,meetingDiscussionRegistrationAttachment

  Response 200: { "success": true, "message": "Xóa tệp đính kèm thành công!" }


────────────────────────────────────────────────────────────────────────────────
4. POLICY
────────────────────────────────────────────────────────────────────────────────

Owner-or-chair-or-op:
  - Owner đăng ký (đại biểu đăng ký = participant.attendee.user_id) → được sửa/xóa
    attachment của đăng ký mình.
  - Chair / Operator của meeting → được sửa/xóa attachment của bất kỳ đăng ký
    nào trong meeting đó (consistent với policy update đăng ký).
  - Đại biểu khác → 403.
