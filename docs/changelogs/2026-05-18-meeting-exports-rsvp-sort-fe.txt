1. ENDPOINT MỚI — XUẤT XÁC NHẬN THAM GIA (RSVP)
────────────────────────────────────────────────────────────────────────────────

Endpoint:
  GET /api/meetings/{meeting}/participants/export-rsvp
  Gate: can:operate,meeting  (chair/op pure FK)

Filename Content-Disposition:
  export__xac-nhan-tham-gia_HH-mm-ss_dd-MM-yyyy.xlsx

Cột Excel:
  STT | Tên đại biểu | Chức vụ | Xác nhận tham gia | Lý do | Thời gian phản hồi

  - "Xác nhận tham gia": map response_status — "Đồng ý" / "Từ chối" / "Chưa phản hồi".
  - "Lý do": chỉ hiển thị khi response_status = declined (absence_reason field).
  - "Thời gian phản hồi": responded_at format H:i:s d/m/Y. Trống nếu pending.

Tách riêng khỏi `/attendances/export` (vốn gộp cả response + điểm danh) —
endpoint cũ vẫn giữ cho FE có nút "Xuất điểm danh" gộp cả 2 thông tin.

Ví dụ:
  STT | Tên đại biểu        | Chức vụ        | Xác nhận tham gia | Lý do              | Thời gian phản hồi
  ----+---------------------+----------------+-------------------+--------------------+--------------------
    1 | Trần Văn Đại Biểu 1 | Đại biểu HĐND  | Đồng ý            |                    | 09:00:00 12/05/2026
    2 | Phạm Thị Đại Biểu 2 | Trưởng phòng   | Từ chối           | Bận công tác       | 10:30:00 12/05/2026
    3 | Hoàng Văn Đại Biểu 3| Phó trưởng     | Chưa phản hồi     |                    |

2. EXPORT THẢO LUẬN / CHẤT VẤN — SORT MỚI + ĐÍNH KÈM CHÍNH XÁC
────────────────────────────────────────────────────────────────────────────────

Endpoints (không đổi URL):
  GET /api/meetings/{meeting}/discussion-registrations/export
  GET /api/meetings/{meeting}/discussion-registrations/export-mine

2.1 Sort priority mới (theo spec):
  Trước: orderBy(sort_order) → orderBy(id)
  Sau:   orderBy(meeting_agenda_id NULLS LAST) → orderBy(created_at)

  Logic:
    - Đăng ký gắn agenda nào → group theo agenda, agenda id nhỏ trước.
    - Trong cùng agenda → thời gian đăng ký cũ nhất trước (created_at ASC).
    - Đăng ký không có agenda (NULL) → đẩy xuống cuối.

2.2 Cột "Đính kèm" check chính xác hơn:
  Trước: $item->media_id ? 'Có' : 'Không'  (chỉ check legacy single attachment)
  Sau:   $item->attachments->isNotEmpty() || $item->media_id ? 'Có' : 'Không'
         (ưu tiên multi-attachment table, fallback media_id cho data cũ
         chưa migrate xong)

  Sau task #11 multi-attachment, attachments[] mới là source of truth. Logic
  fallback media_id giữ để file Excel hiện đúng cho data legacy còn sót.

4. CARD THỐNG KÊ XÁC NHẬN THAM GIA (#21) + BÁO VẮNG KÈM LÝ DO (#22)
────────────────────────────────────────────────────────────────────────────────

4.1 Stats endpoint (mới register nested):
  GET /api/meetings/{meeting}/participants/stats
  Gate: can:viewParticipant,meeting (user có role trong meeting)

  Hoặc dùng flat: GET /api/meeting-participants/stats?meeting_id={m}

  Response data giờ có thêm `pending`:
    {
      "total":    7,
      "accepted": 5,  // "Tham gia"
      "declined": 1,  // "Báo vắng"
      "pending":  1   // "Chưa xác nhận"  (MỚI)
    }

  FE map card:
    - Tham gia       → accepted
    - Báo vắng       → declined
    - Chưa xác nhận  → pending

4.2 Validate báo vắng kèm lý do:
  Endpoint: PATCH /api/meetings/{m}/participants/{p}/respond
            (cùng RespondMeetingParticipantRequest)

  Trước: absence_reason `nullable`.
  Sau:   absence_reason `required_if:response_status,declined|nullable|string|max:1000`.

  Khi đại biểu chọn "Từ chối" mà không nhập lý do → BE trả 422:
    { "absence_reason": ["Lý do vắng là trường bắt buộc khi báo vắng."] }

  Accept (Đồng ý) → absence_reason vẫn nullable (không cần gửi).

HOTFIX route DELETE attachment
────────────────────────────────────────────────────────────────────────────────

Bug: Symfony Route Compiler giới hạn 32 ký tự cho variable trong route pattern.
URL `/meetings/{m}/discussion-registrations/{r}/attachments/{meetingDiscussionRegistrationAttachment}`
có param 39 ký tự → throw DomainException khi register route → mọi request
trong file routes/meeting.php fail (cả /participants/stats không liên quan).

Fix: rename URL param thành `{discAttachment}` (14 ký tự) + thêm
Route::model('discAttachment', MeetingDiscussionRegistrationAttachment::class)
để Route Model Binding vẫn resolve đúng model.

URL DELETE attachment trước vs sau:
  Trước: DELETE /api/meetings/{m}/discussion-registrations/{r}/attachments/{meetingDiscussionRegistrationAttachment}
         (BROKEN — toàn bộ routes file fail load)
  Sau:   DELETE /api/meetings/{m}/discussion-registrations/{r}/attachments/{discAttachment}

FE chỉ cần thay segment cuối — value truyền vào không đổi.
