================================================================================
FE NOTE — Điểm danh cuộc họp (3 method: button / qr / manual)
================================================================================

BE đã ship 3 endpoint điểm danh tương ứng 3 use case. FE phân biệt UI theo role
+ context.

| Method | Endpoint                                          | Caller          | Status mặc định       |
|--------|---------------------------------------------------|-----------------|-----------------------|
| button | POST /api/meeting-attendances/checkin             | Đại biểu (self) | pending (chờ duyệt)   |
| qr     | POST /api/meeting-attendances/checkin-by-token    | Đại biểu (self) | pending (chờ duyệt)   |
| manual | POST /api/meeting-attendances/manual-checkin      | Thư ký/operator | present hoặc absent   |

Phân biệt:
- button: đại biểu mở app, vào Tab 1 cuộc họp đó, bấm nút "Điểm danh".
- qr: đại biểu scan QR (in giấy / projector) → mở URL FE → FE auto submit.
- manual: thư ký Tab 7 click row đại biểu trong list → confirm có mặt hoặc vắng.

Tất cả 3 broadcast WS event `attendance.checked-in` trên channel `meeting.{id}`
→ Tab 7 operator thấy realtime list cập nhật.


--------------------------------------------------------------------------------
1. KIẾN TRÚC
--------------------------------------------------------------------------------

Mỗi cuộc họp có sẵn 1 UUID `checkin_token` (BE auto-generate khi tạo meeting).
Operator/chair gen QR encode 1 URL FE. Đại biểu scan QR → trình duyệt mở URL FE
→ FE đọc token + auth → call BE submit điểm danh.

Flow:
  [QR scan] → mở URL FE → FE check auth
                          ├── chưa login → redirect /login?redirect=/checkin/{token}
                          │                  → sau login quay lại
                          └── đã login → POST /api/meeting-attendances/checkin-by-token
                                          → success: hiện toast "Điểm danh thành công, chờ duyệt"
                                          → fail: hiện error message từ BE


--------------------------------------------------------------------------------
2. URL FORMAT QR
--------------------------------------------------------------------------------

QR encode URL FE (không phải URL BE), ví dụ:

  https://danatec-core.theworkpc.com/checkin/{checkin_token}

  hoặc query-string:
  https://danatec-core.theworkpc.com/checkin?token={checkin_token}

FE setup route `/checkin/:token` (hoặc query) — landing page xử lý logic auth + call API.


--------------------------------------------------------------------------------
3. GET checkin_token (chỉ privileged)
--------------------------------------------------------------------------------

`checkin_token` KHÔNG còn nằm trong `MeetingResource` mặc định (tránh leak).
Phải fetch qua endpoint riêng:

  GET /api/meetings/{meeting}/qr-token
  Permission: meetings.showQrCode (chỉ chair/op/secretary/admin có)

Response:
  {
    "success": true,
    "data": {
      "meeting_id": 1,
      "token": "65f4ca49-8172-4c16-b81c-dd3904f425dc"
    }
  }

UI gen QR:
  - Tab 7 Điều hành có button "Hiện QR điểm danh".
  - Click → fetch GET /meetings/{id}/qr-token → render modal full-screen.
  - QR data: `${window.location.origin}/checkin/${token}` (FE pick path).
  - Lib gợi ý: qrcode.js / vue-qrcode / qrcode.react.
  - Operator chiếu QR lên màn chiếu hoặc in giấy.

Code mẫu (Vue/React):
```js
async function showQrModal(meeting) {
  const r = await api.get(`/meetings/${meeting.id}/qr-token`)
  const url = `${window.location.origin}/checkin/${r.data.data.token}`
  modal.show({ qrData: url, title: meeting.title })
}
```

> Vai trò không có permission `meetings.showQrCode` → 403. Đại biểu thường KHÔNG
> thấy nút "Hiện QR" — chỉ chair/op/secretary thấy.


--------------------------------------------------------------------------------
4. FE ROUTE /checkin/:token
--------------------------------------------------------------------------------

```js
// router setup
{ path: '/checkin/:token', component: CheckinPage }

// CheckinPage
async function onMounted() {
  const token = route.params.token

  if (!authStore.isLoggedIn) {
    // Lưu intent + redirect tới login
    return router.replace({
      path: '/login',
      query: { redirect: `/checkin/${token}` }
    })
  }

  try {
    const r = await api.post('/meeting-attendances/checkin-by-token', { token })
    toast.success(r.data.message)  // "Đã ghi nhận điểm danh qua QR, chờ duyệt."
    router.replace(`/meetings/${r.data.data.meeting_id}`)
  } catch (e) {
    if (e.response?.status === 404) {
      toast.error('QR không hợp lệ hoặc đã hết hạn.')
    } else if (e.response?.status === 422) {
      toast.error(e.response.data.message)  // "Cuộc họp chưa ban hành" / "Bạn không phải đại biểu"
    } else {
      toast.error('Lỗi điểm danh.')
    }
  }
}
```

Login page redirect:
```js
async function login(credentials) {
  await authStore.login(credentials)
  const target = route.query.redirect || '/'
  router.replace(target)
}
```


--------------------------------------------------------------------------------
5. BE ENDPOINT
--------------------------------------------------------------------------------

POST /api/meeting-attendances/checkin-by-token
Headers:
  Authorization: Bearer {token}
  X-Organization-Id: optional (BE tự set theo meeting)
Body:
  { "token": "65f4ca49-8172-4c16-b81c-dd3904f425dc" }

Permission: meeting-attendances.checkin (cùng quyền với button thường).

BE behavior:
  1. Lookup meeting bằng token. Sai → 404 "QR điểm danh không hợp lệ".
  2. Meeting status != 'published' → 422 "Cuộc họp chưa ban hành".
  3. Meeting đang attendance_locked=true → 422 "Đã khoá điểm danh".
  4. User không phải participant của meeting → 404 "Bạn không phải đại biểu".
  5. Idempotent qua unique (meeting_id, participant_id) — F5/scan lại không tạo trùng.
  6. checkin_method = 'qr' (phân biệt với 'button' trong báo cáo).
  7. Status mặc định = 'pending' chờ operator duyệt (Tab 7 DUYỆT ĐIỂM DANH).
  8. Broadcast WS event `attendance.checked-in` trên channel `meeting.{id}` →
     operator/chair Tab 7 thấy realtime list "đang chờ duyệt" cập nhật.

Response success (201):
  {
    "success": true,
    "message": "Đã ghi nhận điểm danh qua QR, chờ duyệt.",
    "data": {
      "id": 12,
      "meeting_id": 1,
      "meeting_participant_id": 5,
      "status": "pending",
      "checkin_method": "qr",
      "checked_in_at": "08:30:00 15/05/2026",
      ...
    }
  }


--------------------------------------------------------------------------------
6. UX EDGE CASES
--------------------------------------------------------------------------------

- **User scan QR khác meeting họ tham gia**: BE 404 "Bạn không phải đại biểu" → FE
  hiển thị error rõ ràng, gợi ý liên hệ thư ký.

- **F5/scan lại sau khi đã điểm danh**: BE return 201 với row hiện có (idempotent).
  FE chỉ cần show "Đã điểm danh trước đó" hoặc redirect trang meeting.

- **Operator đã khoá điểm danh**: BE 422 "Danh sách điểm danh đã đóng".

- **Meeting bị huỷ giữa chừng**: BE 422 "Cuộc họp chưa ban hành".

- **Token bị rò rỉ ra ngoài**: không có rủi ro vì BE vẫn check auth + participant —
  chỉ user là đại biểu của meeting đó mới điểm danh được.


--------------------------------------------------------------------------------
7. THƯ KÝ ĐIỂM DANH HỘ (manual)
--------------------------------------------------------------------------------

Use case: đại biểu không dùng app (offline), thư ký/operator submit hộ trên
Tab 7 Điều hành. UI gợi ý:

- Tab 7 có panel "DANH SÁCH ĐẠI BIỂU" hiển thị tất cả participants của meeting.
- Mỗi row có:
    - badge status hiện tại (chưa điểm danh / pending / present / absent)
    - 2 button "Có mặt" + "Vắng mặt" (chỉ visible cho row chưa có status final)
- Click button → modal confirm + optional note → submit BE.

Endpoint:

  POST /api/meeting-attendances/manual-checkin
  Headers:
    Authorization: Bearer {token}
    X-Organization-Id: {organization_id}
  Body:
    {
      "meeting_id": 1,
      "meeting_participant_id": 12,
      "status": "present",          // hoặc "absent"
      "note": "Đã xác nhận qua điện thoại"  // optional
    }

  Permission: meeting-attendances.store (chỉ chair/op/secretary/admin có).

  BE behavior:
    - Validate participant thuộc đúng meeting (chặn cross-meeting).
    - Status chỉ chấp nhận "present" hoặc "absent" (không phải "pending").
    - Idempotent: F5/click lại với cùng status → update row hiện tại.
    - checkin_method = 'manual' (phân biệt báo cáo).
    - checked_in_by = auth user (thư ký), KHÔNG phải participant user.
    - Broadcast WS attendance.checked-in.

  Response (201):
    {
      "success": true,
      "message": "Đã điểm danh hộ đại biểu.",
      "data": {
        "id": 12,
        "meeting_id": 1,
        "meeting_participant_id": 12,
        "status": "present",
        "checkin_method": "manual",
        "checked_in_at": "10:15:00 15/05/2026",
        ...
      }
    }

UX gợi ý:
- Sau khi submit thành công → row trong list đổi badge → status mới.
- Toast thông báo: "Đã điểm danh: {participant_name} - Có mặt".
- Nếu meeting đang `attendance_locked=true` → BE 422 "Danh sách điểm danh đã đóng",
  FE disable buttons + show banner cho operator.

Code mẫu:
```js
async function manualCheckin(participant, status) {
  const note = status === 'absent' ? await promptNote() : null
  try {
    await api.post('/meeting-attendances/manual-checkin', {
      meeting_id: meeting.id,
      meeting_participant_id: participant.id,
      status,
      note,
    })
    toast.success(`Đã điểm danh: ${participant.name} — ${status}`)
  } catch (e) {
    toast.error(e.response?.data?.message ?? 'Lỗi điểm danh hộ')
  }
}
```

8. TÓM TẮT VIỆC FE
--------------------------------------------------------------------------------

QR (đại biểu scan):
1. [ ] Tạo route FE `/checkin/:token` (hoặc query-string).
2. [ ] CheckinPage component: check auth → redirect login hoặc gọi API.
3. [ ] Login page: respect `?redirect=` để quay lại sau login.
4. [ ] Tab 7 (operator) button "Hiện QR điểm danh":
        - Fetch `GET /meetings/{id}/qr-token` (cần permission meetings.showQrCode).
        - Render modal QR từ `${origin}/checkin/${token}` (lib qrcode.js).
        - Hide button cho user không có permission.
5. [ ] Toast/UI feedback theo response status (201/404/422).

Manual (thư ký hộ):
6. [ ] Tab 7 panel "DANH SÁCH ĐẠI BIỂU" hiển thị participants với badge status.
7. [ ] Mỗi row có 2 button "Có mặt" / "Vắng mặt" → modal confirm + note → POST manual-checkin.
8. [ ] Disable buttons khi `meeting.attendance_locked=true` + show banner.

Realtime (mọi method):
9. [ ] Listen WS `attendance.checked-in` trên Tab 7 — append/update list realtime
       khi 1 trong 3 method submit (button/qr/manual đều bắn cùng event).
10. [ ] Listen WS `attendance.approved` / `attendance.rejected` để list "đang chờ
        duyệt" (status=pending) cập nhật khi operator duyệt.
